# PA3: fine-tuning Qwen3-0.6B, VLM grounding, test-time compute

Course project (EE-5102 / CS-6304). Three tasks:

1. **Task 1, LLM fine-tuning.** Qwen3-0.6B on MetaMathQA with Full FT, L2-SP, LoRA r=4, LoRA r=16 and OPLoRA r=16.
2. **Task 2, vision-language grounding.** SigLIP features, a trainable connector and LoRA on Qwen3-0.6B, trained on COCO and VQA v2 pairs.
3. **Task 3, test-time compute.** Repeated sampling, answer selection and adaptive stopping on supplied MATH and MathVista rollouts, plus a live refinement run on 50 MATH questions.

## Task 1: LLM fine-tuning

1. Training runs on Kaggle. The notebooks download MetaMathQA, GSM8K and the Qwen3-0.6B weights from Hugging Face. Settings are in `configs/task1_runs.json`.
2. Full FT and L2-SP: `task1/kaggle/kaggle_task1_full_l2sp.ipynb`. LoRA and OPLoRA: `task1/kaggle/kaggle_task1_lora.ipynb`. Each writes a zip of its outputs. Save the zip under `artifacts/task1/`.
3. Merge a LoRA or OPLoRA adapter into a full model, with a logit check:
   ```bash
   .venv/bin/python task1/merge_adapters.py --adapters <run>/snapshot_1250/adapters.pt --out <out_dir>
   ```
4. Evaluate locally. Run with `--help` to see the flags:
   ```bash
   .venv/bin/python task1/eval_task1.py --help
   ```
5. Diagnostics, qualitative outputs and the report: `task1/diagnostics_task1.py`, `task1/qualitative_task1.py`, `task1/report_task1.py`.

Kaggle outputs keep the training logs and summaries in `results/task1/`. Weights stay in `artifacts/`.

## Task 2: vision-language grounding

Run from the repo root, in this order:

```bash
bash task2/fetch_data.sh                       # COCO 2014 and VQA v2, about 26 GB
.venv/bin/python task2/prep_data.py            # splits and pools, writes data/task2/manifests
.venv/bin/python task2/cache_features.py mps   # SigLIP features, about 6 GB
bash task2/run_task2_all.sh                    # train, eval and report into artifacts/task2/main
.venv/bin/python task2/eval_untrained.py --run artifacts/task2/main        # pre-training baseline
.venv/bin/python task2/make_extra_figs.py --run artifacts/task2/main      # extra figures
```

`scripts/run_local_queue.sh` is the queue used for the first MPS runs. It is kept as a record.

## Task 3: test-time compute

Inputs are the supplied rollouts (ATML-PA3-Data) under `artifacts/task3/data/ATML-PA3-Data` and the MathVista testmini metadata at `artifacts/task3/mathvista/testmini.json`. Splits (200 development, 800 held out, first 50 held-out MATH questions for the live run) and the ten question orders come from seed 6304 (`task3/common.py`). Gold answers are loaded separately and used only for grading.

```bash
.venv/bin/python task3/offline.py --out results/task3/offline              # grading, selection rules, adaptive stopping, bootstraps
.venv/bin/python task3/live.py run --out artifacts/task3/live --device mps # live run on 50 MATH questions, 3,072-token allowance
.venv/bin/python task3/live.py summarize --out artifacts/task3/live --results results/task3/live
.venv/bin/python task3/rq2_checks.py                                       # vote versus score checks
.venv/bin/python task3/trajectories.py --results results/task3 --figures <figure_dir>
.venv/bin/python task3/report_task3.py --results results/task3 --tables <table_dir> --figures <figure_dir>
```

## Attribution

**Models:** Qwen3-0.6B, Qwen2.5-3B-Instruct and Qwen2.5-VL-3B-Instruct (Qwen team, Alibaba); SigLIP `google/siglip-base-patch16-224` (Zhai et al., 2023).

**Datasets:** MetaMathQA; GSM8K; HellaSwag; BoolQ; ARC-Easy (via Hugging Face); COCO 2014; VQA v2 (Goyal et al., 2017); MATH and MathVista testmini, through the supplied Task 3 rollouts (ATML-PA3-Data).

**Evaluation:** EleutherAI lm-evaluation-harness 0.4.13, used for all Task 1 benchmarks. `math-verify` grades MATH answers in Task 3.

**Reused code:**
- `task2/vqa_contractions.py` ports the contraction table from the official VQA evaluation code (GT-Vision-Lab/VQA, `vqaEvaluation/vqaEval.py`).
- `task3/answers.py` follows the MathVista answer-type and precision rules from the released question metadata.
- `task1/diagnostics_task1.py` copies `hs_preprocess` and `hs_query` from the lm-evaluation-harness HellaSwag task.

**Methods and papers:** Self-consistency (Wang et al., 2023); self-certainty (Kang et al., 2025); VisConf (Usman et al., 2026); Self-Refine (Madaan et al., 2023); Large Language Monkeys (Brown et al., 2024); LoRA (Hu et al., 2021); OPLoRA (Xiong and Xie, AAAI 2026); L2-SP (Li et al., ICML 2018); two-stage visual instruction tuning idea from LLaVA (Liu et al., 2023). Our connector is a 2-layer MLP on SigLIP features, not LLaVA's linear projection on CLIP features; LoRA Learns Less and Forgets Less (Biderman et al., 2024).

**Course material:** the Task 3 rollouts, specification and starter assets are from the ATML PA3 course staff. Libraries: PyTorch, Hugging Face Transformers, PEFT, datasets, NumPy, pandas, matplotlib, pyarrow, `math-verify`.

**Coding assistance:** Claude Code was used for help in writing the code. I reviewed the code and am responsible for it.

No other external code was reused.
